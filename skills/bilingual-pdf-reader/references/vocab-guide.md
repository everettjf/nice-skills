# 生词行规范

译文下方那行「生词」，是这份双语稿区别于普通机翻的地方。格式固定，密度有度。

## 格式

```
生词：**stoop** /stuːp/ *n.* （美）楼门前的台阶 · **catch up with** /kætʃ ʌp wɪð/ *词组* 追上；（苦日子）找上门
```

固定顺序：**词条 + 音标 + 词性 + 释义**；词条写原文（不写原形化的形式，除非原文就是原形），音标用斜杠包住，词性用斜体，条目之间用 ` · ` 分隔。一段一行，不要把一段拆成多行。

- 音标统一用**美式**（故事、新闻、教材多为美式；用户指定英式就统一英式）。词组给完整音标。
- 词性取值限定在：`n. v. vt. vi. adj. adv. prep. conj. pron. num. int. aux. abbr. 词组 习语 俚语 专名`。
- 释义用中文，**先给最贴合这句语境的义项**，其他常用义项用分号补在后面（`追上；（苦日子）找上门`）。
- 释义不要写成词典式长句，能三五个字说清就三五个字。

## 收哪些词

按「中文母语者读这段会不会卡一下」来判断，不是按词频表。

**基本都收：**

1. 原文自带的脚注词、生词表词——上课要考的，必须收，并在释义后标「（原文脚注词）」。
2. 超出四六级常规范围的实词：`stoop`、`tenement`、`ajar`、`musty`、`creaky`、`throb`、`looming`。
3. **词组和习语**——查到每个单词也读不懂的：`the next best thing`、`knit one's brows`、`let up`、`the coast is clear`、`mess with`。
4. 一词多义里在**这一段**用了生僻义项的：`strain`（使劲）、`spell`（一小会儿）、`nerve`（胆量）。
5. 拟人、老式、方言说法：`mouth fiddle`、`pappy`、`spook`、`rag man`。

**不收：**

- 常见的功能词、基础动词（make、take、look、get）。
- 专有名词（人名、地名、队名）——除非有文化背景需要说明，放译注更合适。
- 中文读者几乎不会卡的词（school、letter、rain）。

**密度**：每段 0–4 条，平均 1–2 条。宁缺毋滥；一段挤七八条会让人不想看。如果某段确实有 6 个以上难词（比如角色一口气说了三句方言），就挑最影响理解的那几个，剩下的靠译文解决。

## 音标准确性

音标写错比不写更糟。写不准的时候：

1. 只在**有把握**时标音标；拿不准就省掉音标（校验脚本会提醒缺失，但错音标是错的，缺音标只是不完美）；
2. 词组音标按词逐个标，重音标在实词上；
3. 常见易错点：`-ed` 后接清辅音的读法、`th` 的 /θ/ 与 /ð/、双写元音的长音、美式 r 音（`/ˈpɑːrlər/` 而不是 `/ˈpɑːlə/`）。

## 自检

```bash
python3 scripts/check_bilingual.py bilingual.md
```

脚本会检查格式、音标斜杠、词性取值，并提示「生词似乎没出现在该段英文里」。最后一条要人工判断：它可能是

- 真的放错了段（把词条挪到它出现的段落）；
- 词形变化（`catch` vs `caught`、`strain` vs `straining`）——这种情况把词条写成原文里的形式更好，读者更容**在文里找到它**。
